# Developing Wallflower

Notes for contributors: how the code is laid out, how to build, test and debug it, and why the less obvious parts work the way they do. For the user-facing overview, see the [README](../README.md). For the Claude Code files Wallflower reads, see [registry-format.md](registry-format.md); for the session files other tools write, [external-sessions.md](external-sessions.md).

The product is called Wallflower, and so is the executable product (`.build/debug/Wallflower`). The Swift target, module and source folders keep their working name, `AgentOverview`, so you will see both.

## Architecture map

| Folder | What lives there |
|---|---|
| `Sources/AgentOverview/App/` | AppKit lifecycle (`main.swift`, `AppDelegate`), the panel window and its placement on the screen edge, the menu bar item, launch arguments, the in-process window snapshot, `AppInfo` (public name, bundle id, author and studio, links). |
| `Sources/AgentOverview/Data/` | The session registry: decoding `~/.claude/sessions/<pid>.json`, watching the folder, the `SessionStore`, the session identity (`SessionKey`, `SessionSnapshot`). `External/` reads the session files other tools write. `Transcript/` reads transcript tails for the working substate, subagent count and git branch. `Actions/` holds the action faces. Timing constants live in `DataTuning.swift`. |
| `Sources/AgentOverview/UI/` | The panel: `PanelModel`, the capsule, rows, the goo hover bulge, row arrival and departure, magnification. `Theme.swift` holds every tunable visual value. |
| `Sources/AgentOverview/Eyes/` | The faces. The dot-matrix style at the top level, the blob style in `Blob/`, the screen filters in `Filters/`. Everything animates in Core Animation. |
| `Sources/AgentOverview/Playground/` | The face playground window, for tuning faces at a large size. |
| `Tests/AgentOverviewTests/` | swift-testing suites. |
| `Tests/Fixtures/` | Anonymised registry files and transcript snippets used by the tests. |
| `Packaging/` | `Info.plist` (`LSUIElement`, bundle id `dev.wallflower.Wallflower`, minimum macOS 26) and `AppIcon.icns`. |
| `scripts/` | Bundling, running, releasing and the icon, plus `wallflower-session`, the helper other tools call to write their session files. |

## Build

- Toolchain: Command Line Tools for macOS 26 (no Xcode needed). SwiftPM with `swift-tools-version: 6.2` (needed for `.macOS(.v26)`), Swift language mode 6. Development happens on Swift 6.4.
- `swift build` builds the debug executable, `.build/debug/Wallflower` (`swift build --show-bin-path` prints the folder). `swift build -c release` builds the release one.
- `scripts/bundle.sh` builds the release binary and assembles `build/Wallflower.app` (Info.plist and icon from `Packaging/`, ad hoc signed). Extra arguments go to `swift build`, for example `--arch arm64 --arch x86_64`.
- `scripts/run.sh` stops a running instance, bundles and launches it. It stops the app by process name, so it also stops a copy you started from another checkout.
- `scripts/release.sh` builds `build/release/Wallflower-<version>.zip` (universal when the toolchain can, arm64 otherwise, ad hoc signed) and prints its SHA-256. It never uploads anything.
- `scripts/make-icon.sh` renders the app icon with the app's own face renderer (`--render-icon`, `App/IconRenderer.swift`) and writes `Packaging/AppIcon.icns` and `docs/assets/icon.png`. Commit both.
- The Command Line Tools ship no SwiftUI macro plugin, so `@State` does not compile here. Views keep their state in `@Observable` objects (`PlaygroundModel`, `PanelModel`) instead.

## Test

- `swift test` runs everything. The tests use swift-testing (`import Testing`), which works with plain Command Line Tools; XCTest is not used.
- Fixtures in `Tests/Fixtures/` are copied as test resources. `Package.swift` passes the Command Line Tools' swift-testing macro plugin path to the test target explicitly, because the default build system does not find it on its own.
- Fixtures must stay anonymised: no real names, paths, session ids or socket paths. `cwd` values live under `/Users/demo/`.

## Run and debug

Run the bare debug binary to try a change without bundling:

```sh
swift build
"$(swift build --show-bin-path)/Wallflower" --sessions-folder /path/to/fake/sessions
```

Sessions from other tools come from `--external-sessions-folder <path>`: a folder of `<id>.json` files shaped like `Tests/Fixtures/external/*.json`, easiest written with `WALLFLOWER_SESSIONS_DIR=<path> scripts/wallflower-session start ...`. Without that argument the app reads the real `~/Library/Application Support/Wallflower/sessions`.

A fake registry is a folder of `<pid>.json` files shaped like `Tests/Fixtures/*.json`. The pid must belong to a live process (the scanner skips dead ones), so start a few `sleep 1200 &` and use their pids. `docs/assets/make-hero.sh` does exactly that to render the README hero image, and is a good starting point.

Logs go to the unified log under the subsystem `dev.wallflower.Wallflower`:

```sh
log stream --predicate 'subsystem == "dev.wallflower.Wallflower"'
```

### Launch arguments

All of these are for scripted checks and debugging; none is needed for normal use.

| Argument | Effect |
|---|---|
| `--sessions-folder <path>` | Read another registry folder instead of `~/.claude/sessions`. |
| `--actions-file <path>` | Read the action faces from another file. |
| `--external-sessions-folder <path>` | Read other tools' session files from another folder instead of `~/Library/Application Support/Wallflower/sessions`. |
| `--external-sessions <on\|off>` | Show sessions from other tools or not, overriding the stored setting. |
| `--vertical-offset <pt>` | Place the panel this far above the screen's vertical centre (negative is below), ignoring the stored position. Drags and "Reset position" persist nothing in that run. |
| `--hover <row\|action:<index>\|new\|none>` | After the first scan, hover a row (or an action row, or the new session button with `new`) with the model pointer on its centre. A real pointer cannot be scripted without Accessibility. |
| `--hover-sequence 0,2,none` | Step through hover targets, one every 1.2 s, and stay on the last. |
| `--pointer-glide <from>,<to>,<seconds>` | Move the model pointer down the capsule's centre line from one slot to another, hold, release. Steps every 16 ms, so debug only. Useful for filming the magnification with `screencapture`. |
| `--gesture-script <step;step;...>` | Press, move and release on the panel with synthetic events posted to the app's own event queue, the path a real pointer takes. Steps: `drag:<slot>:<dx>,<dy>:<ms>` (eased, released at rest), `flick:<slot>:<dx>,<dy>:<ms>` (constant speed, released while moving; a throw is a negative `dx` on the right edge and a positive one on the left), `wait:<ms>`, `menu` (logs the "Show hidden sessions" item), `unhide` (chooses it). Row clicks only log in this mode. |
| `--open-first` | Click the top row with a synthetic event after the first scan, log the frontmost app before and after, then quit. |
| `--run-action <index>` | Click an action row for real (the launcher runs). |
| `--snapshot <path>` | Write a PNG of the panel after `--snapshot-delay` seconds (default 1.5), then quit. |
| `--snapshot-window <playground\|settings-<tab>\|welcome-<page>\|menu-glyph>` | Snapshot another window instead of the panel: the playground, a Settings tab (`general`, `appearance`, `about`; its sheet instead when one is attached, see `--edit-action`), a welcome page (1 to 4) or the menu bar glyph in both states. |
| `--snapshot-burst <count>:<ms>` | Write a numbered series of snapshots that far apart. |
| `--snapshot-grow <start>:<step>` | Burst frames show the attention grow evaluated per frame. |
| `--snapshot-scale <factor>` | Pixels per point (default 2). |
| `--snapshot-method <layer\|view\|screenCaptureKit>` | In-process layer render (default), AppKit drawing plus the layer walk for the faces (`view`, right for Settings and the welcome), or the window server, which needs Screen Recording. |
| `--log-frame` | Log the panel frame whenever it is set and on every screen-parameter, Space or occlusion change. |
| `--log-insights` | Log pid, activity, subagent count and branch on every change. Never logs names, paths or content. |
| `--defaults-suite <name>` | Read and write settings in this `UserDefaults` suite instead of the app's own, so checks never touch a real setup. |
| `--set <key>=<value>` | Change a setting after the first scan, the way Settings would (live rebuild included). Keys follow `AppSettings`; `newSessionButton=on\|off`, `externalSessions=on\|off` and `launchAtLogin=on\|off` too. |
| `--session-source <desktop\|terminal\|everywhere>` | Which sessions to show, overriding the stored setting. |
| `--side <left\|right>` | The screen edge the panel docks to, overriding the stored setting (`--set panelSide=left` switches it live after the first scan instead). |
| `--action-launcher <terminalCommand\|deepLinkAndSend\|deepLinkNew>` | How action faces run, overriding the stored setting. |
| `--show-settings <general\|appearance\|about>` | Open Settings on that tab at launch. `--settings-advanced` also opens the Advanced section. |
| `--edit-action <index\|new\|select:<index>>` | With Settings open on General: open the action editor sheet for that action or a new one, or only select a row (scrolled into view). A `settings-general` snapshot then captures the sheet when one is attached. |
| `--welcome <1-4>` | Open the welcome on that page. `--no-welcome` keeps it closed even on a first launch. `--welcome-keys <keys>` presses keys in it (comma separated, such as `return,return,escape`). |
| `--log-menu` | Log the menu bar menu's items (a menu cannot be captured offscreen). |
| `--render-icon <folder>` | Write the app icon set into the folder and quit before any window exists (used by `scripts/make-icon.sh`). |
| `--playground` | Open the face playground at launch. `--retina` puts it on the sharpest screen. |
| `--excite <seconds>` | That long after the first scan, every working row's face plays the excited reaction as if its session had just started working (`PanelModel.exciteWorkingRows`); in the playground (`--playground`) the heroes get it instead. For `--snapshot-burst` frames of the reaction; the real trigger is a status change. |
| `--activity <thinking\|coding\|running\|reading\|delegating>`, `--satellites <n>`, `--hop <seconds>`, `--waiting-kind <question\|permission>`, `--hovered` | Playground: the working substate, the satellite count, a scripted hop, the needs-input kind, and hover every hero face. |
| `--demo-states` | Force the first two rows into working states with satellites and a branch, to judge the visuals on any registry. |
| `--face-style <dotMatrix\|blob>` | Override the face style. |
| `--face-filter <none\|dotMatrix\|asciiGrid\|halftone\|scanlines>` | Override the screen filter. |
| `--blob-shape <status\|identity>` | What the blob silhouette means. |
| `--color-mode <status\|identity\|project>` | What the body colour means. |
| `--hover-effect <magnify\|stretch\|none>` | What a hover does to the faces. |
| `--goo <blurThreshold\|path>` | The goo renderer. |
| `--expand <row\|all>` | Bulge the hovered row only, or widen the whole capsule. |

`--snapshot` uses `WindowSnapshot` (`App/WindowSnapshot.swift`), which renders the window's own Core Animation presentation tree in-process: a walk that applies transforms, masks and flips itself, because `CALayer.render(in:)` ignores transforms and the root's flip, and because the snapshot should work on a machine where no process holds Screen Recording. The image is composited over a flat grey. The walker applies sublayer transforms too, so a throw can be filmed with `--gesture-script` and `--snapshot-burst`. It draws a layer's shadow when it has a `shadowPath` (the halo, the dot-matrix glow) with `CGContext.setShadow`: Core Graphics' blur is twice Core Animation's `shadowRadius` (both measured), and the path is filled far outside the image with the shadow offset back, so only the shadow lands. Filters are not drawn. It does not show an in-flight spring; use `screencapture` for the genie stretch.

## The performance contract

Wallflower sits on screen all day, so this is not negotiable:

- 0 % CPU at rest. No polling and no repeating timers. File changes arrive as `DispatchSource` events; every loop (blinks, breathing, gaze, pulses, orbits) is a Core Animation animation that runs in the render server.
- Nothing ticks while the panel is collapsed. The `Needs input · 2m` clock is a `TimelineView` that only exists while a bulge is open, and it ticks once a minute.
- One window resize per transition, never per frame (see "Window geometry" below).
- Under about 30 MB of memory. Transcript reads are bounded tails, and results are cached by file size and modification time.
- No network access at all.

## Implementation notes

### App and window

- `PanelWindow` is an `NSPanel` subclass that never becomes key. `PanelHostingView` accepts the first mouse for that reason, and owns the one `NSTrackingArea` (`.activeAlways`, so hover works although the panel is never key). It reports pointer positions to the model.
- `PanelPlacement` is pure geometry: the window frame for a state, the capsule height and vertical offset, the offset clamped into the screen's `visibleFrame`. It also holds `PanelDragTracker` (the click-or-drag decision) and `PanelPositionStore` (the `panelVerticalOffset` default). `PanelWindowState` is collapsed, or expanded to a width.
- Window geometry follows one rule: `PanelModel.rowCountDidChange` sets the window's capsule height to the final value immediately when rows are added (the window grows first, the capsule animates inside it) and only after `Theme.closeSpringSettleTime` when rows are removed. Hover does the same with the width (`PanelModel.hover`). One resize per transition, never per frame.
- Placement and drag: the panel's vertical position is an offset of the window centre from the screen's vertical centre, stored in `UserDefaults` as `panelVerticalOffset` (nothing stored means centred). `PanelPlacement` clamps it into the screen's `visibleFrame` with `Theme.dockEdgeInset` to the menu bar and the Dock; a capsule taller than that hangs from the top limit. The offset is the anchor: when the capsule grows it grows up and down around it, when the screens change it is re-clamped, and a capsule pushed off it returns once it fits.
- Panel side (`PanelSide`, `UI/PanelSide.swift`; setting `panelSide`, Settings > General, `--side`): the horizontal geometry is written once, for the right edge, the canonical side. On the left edge the same geometry is mirrored, never re-derived: `PanelSide` holds the mirrors (`mirror(x:in:)` for a coordinate, `mirror(dx:)` for an offset or a velocity, `mirror(_:in:)` and `transform(in:)` for rects, paths and drawing contexts, `faceTransform` for a face), each its own inverse and the identity on the right. Who applies it: `PanelPlacement` puts the window at the screen's `minX` (it grows rightward); `PanelWindow` anchors the hosting view to the container's left edge (`side`, set live, re-anchors and re-places in one step); `PanelRootView` and `CapsuleView` align the content to the edge; `EdgeRow` is the one place that orders a row (face at the edge, bulge beside it), used by the session, action and new session rows and the divider; `BulgeTextFrame` mirrors the bulge text's alignment and paddings (right-aligned at the outer padding on the left); `CapsuleShape` mirrors its own outline; both goo renderers draw the canonical `GooLayout` geometry mirrored (`GooPathShape.path(in:)` mirrors `canonicalPath(in:)`, `GooCanvasView` concatenates `drawingTransform(side:)` in both layers and moves its bleed to the left with `bleedOffset(side:)`; blur and threshold are symmetric); `AttentionEdgeLayout` mirrors the cue onto the capsule's right edge; `PanelModel` measures the pointer from the edge (`PanelSide.distanceFromEdge`) for the hover region and the throw target; `PressAxis` and `FaceThrow` mirror the horizontal travel and velocity into the right edge's frame and the fly-away back out of it. The faces (`FaceView.side`, `FaceConfiguration.side`) are mirrored about their centre by a sublayer transform on the blob's `face` and `haloHost` layers (the dot matrix: `glowGroup` and `dotGroup`), below the magnification, the throw pose and the screen filter mask, so the gaze toward the screen, the genie stretch and shift and the halo silhouette all face right while the filter lattice is never mirrored. The magnification needs no mirror: `PanelModel.pointer` is in the capsule's real coordinates, so a face leans toward the real pointer. Vertical rules (the bulge span, the flush ends, `bulgeTextPlacement`, `MagnifyColumn`, `FaceReach`) are the same on both sides. A change rebuilds the panel content like any other setting, and `installPanelContent` moves the window in the same turn, so window and content never disagree. The vertical offset is shared by both sides.
- Press and drag anywhere on the capsule (faces and bulge included) to move the panel along the edge. `PanelDragController` is a local event monitor on the left-button events, so SwiftUI still gets every event of a plain click (press feedback, first click on the never-key panel, the button action). A press becomes a drag only after more than `Theme.dragThreshold` of vertical travel; then the window follows the pointer 1:1 without animation, the dragged events are kept from SwiftUI, `PanelModel` freezes pointer reports (the hover stays where the press began, re-synced from the real pointer on release) and swallows the tap the release may still produce until the next press. "Reset position" clears the stored offset and eases back to the centre (`Theme.resetPositionDuration`). Hover expansion only ever grows the window away from the screen edge (leftward, or rightward on the left edge). A press that first travels away from the edge instead is a throw (see "Throw a face out" below).
- Space switches: with `.canJoinAllSpaces` + `.fullScreenAuxiliary` + `.stationary` the window server still slid the panel along with a full-screen Space's transition (measured with `CGWindowListCopyWindowInfo` while switching with Control-arrow; `NSWindow.frame` never changed and no screen-parameter notification arrived). Window levels, dropping `.stationary`, `.transient`, `.canJoinAllApplications` and re-ordering on `activeSpaceDidChangeNotification` changed nothing. `PanelWindow.show()` therefore moves the window into a Space of its own (`StationarySpace`: `CGSSpaceCreate` and friends, exported by CoreGraphics but undocumented, looked up with `dlsym`; missing calls fall back to the plain behaviour) at `Theme.panelSpaceLevel` 1, the lowest level that stays visible over full-screen apps. Measured, the panel then does not move at all. That Space sits above every user Space, so the panel also draws above other apps' high-level overlays and menus where they overlap its strip. It orders itself out while the screen saver runs or the screen is locked (distributed notifications) and back in afterwards. `Theme.panelOwnSpace = false` restores the plain behaviour.

### Data

- `SessionRecord` decodes `~/.claude/sessions/<pid>.json`. `SessionRegistryScanner` reads a folder (skips `.key` files, undecodable files and dead pids). `RegistryWatcher` watches the folder plus every tracked file with `DispatchSource` (Claude Code rewrites files in place, so the folder descriptor alone never sees status changes) and debounces 50 ms. When `~/.claude/sessions` (or even `~/.claude`) does not exist yet, it watches the nearest existing ancestor and re-arms one level at a time as folders appear or disappear, so a first install before Claude Code ever ran still picks sessions up. `SessionStore` diffs scan results into `@Observable` `Session` objects (identity: `SessionKey`, see below), ends them on `DispatchSource` process exit, and sorts needs input, working, your turn, idle (newest state first within each; `SessionStore.sorted` is the one place, `SessionState.sortRank(idleTier:)` the ranks). `PanelModel.visibleSessions` re-sorts with the acknowledgements once there are any; without them the store's order already is the tier order, because the your-turn window is the same length for every session.
- Idle tiers (`Data/IdleTier.swift`): an idle session is `yourTurn` while its idle period (the registry's `statusUpdatedAt`, so a relaunch keeps the tier) is younger than `Theme.yourTurnFor` (15 minutes) and the person has not acknowledged it, else `idle`. `IdleTier.tier(idleSince:acknowledgedAt:now:)` is the one rule; `Session.idleTier(acknowledgedAt:now:)` applies it for both the row and the sort. The expiry needs no polling: whenever a session enters an idle period (or its state start moves), `Session` arms one main-actor `asyncAfter` for the end of the window that bumps the observed `yourTurnExpiries`, ignored if the session left that idle period meanwhile. Rows read it through `idleTier`, so they re-derive at that moment.
- Which entrypoints are shown is a filter on the record's `entrypoint` (`DataTuning.defaultEntrypoints`; the desktop app writes `claude-desktop`). It applies to Claude sessions only.
- Identity (`Data/SessionKey.swift`): `SessionKey` is `.claude(pid)` or `.external(id)`, so the two never collide; `SessionSourceKind` is `.claude` or `.external(tool:)`. Everything per session keys on it: the store's process sources, removal tokens and insight readers, `Acknowledgements`, `HiddenSessions`, the hop and excited trackers, the throw (`throwingKey`, `flownPoses`), `hoveredKey` and the capsule's stack ids (`s<pid>` as before, `sx:<id>` for external rows). `SessionKey.description` keeps a Claude key's string the bare pid, so Claude rows behave exactly as before. A Claude face's seed is unchanged (`hostSessionId`, else `pid-<pid>`); an external one's is `external-<id>`. `Session.pid` is optional: always set for Claude, the file's `pid` for external sessions.
- `SessionSnapshot` (`Data/SessionSnapshot.swift`) is one session as a scan saw it, whatever its source: `SessionRecord` and `ExternalSessionRecord` both map to it, and `Session` is built from and updated with it, so the state, the just-finished moment, the your-turn expiry, the sort and the project colour have one code path. `SessionStore.reconcile` has an overload per source; both call `merge`, which only ends sessions of its own source, so a Claude scan never touches external sessions and the other way round. `hasScanned` (and `onFirstScan`) waits for the first scan of every watched source. A key that reappears while its ended session still fades out (an id reused right after `end`) is kept and added once the old row is removed, because no file event may follow. The transcript insight reader starts for Claude sessions only.
- Sessions from other tools (`Data/External/`, format in [external-sessions.md](external-sessions.md)): `ExternalSessionRecord` decodes `<id>.json` leniently (only `id` and `status` required; an optional key of the wrong type reads as absent; `open` is `ExternalOpener`, url over app over command). `ExternalSessionScanner` decides liveness: with a `pid` the process must be alive (the store then watches its exit like a Claude session's), without one the later of `updatedAt` and the file's modification time must be younger than `DataTuning.externalSessionTTL` (10 minutes). A fresh undecodable file counts as present by its name, so a session is not ended mid-rewrite. `RegistryWatcher` takes a scan closure (`init(folder:label:scan:)`); `RegistryWatcher.external` scans this folder and, when a pid-less record will expire, arms one wall-clock rescan at that moment plus `DataTuning.expiryRescanSlack`, replaced by every scan, so nothing polls and a Mac that slept through an expiry rescans on wake. The store watches the folder only when `externalFolder` is set (`AppSettings.externalSessions`, Settings > General > "Sessions from other tools", default on; a change replaces the store like a source change). Measured with two Claude and three external fixture sessions after the first scan: 0.0 % CPU at rest, 28 to 37 MB across runs (32 MB with the external folder off in the same setup).
- `Transcript/`: `TranscriptLocator` maps a record to its transcript and subagent folder, `TranscriptTail` reads a bounded tail (`DataTuning.transcriptTailBytes`), `InsightReader` turns it into a `SessionInsight` (activity, subagent count, git branch, tool errors). `SubagentScanner` counts live subagents, `GitHeadReader` reads `.git/HEAD` without spawning `git` when the transcript has no branch yet. A detached head is no branch (`GitBranchName`), so the bulge shows no branch line for it.
- Timing constants of the data layer live in `DataTuning`, separate from `Theme`.
- Hidden sessions (thrown out of the capsule) are not removed from the store; `PanelModel` filters them (see "Throw a face out" below).

### Panel model and rows

- Settings (`Settings/AppSettings.swift`) hold the look and the session source at runtime; `Theme` only supplies the defaults and launch arguments win over both. A change rebuilds the panel content in `AppDelegate.installPanelContent()`: a new `PanelModel` and root view (`PanelRootView` takes `.id(ObjectIdentifier(model))`, so every face is built fresh with the new look), the same window, `ActionStore` and `HiddenSessions`. A source change replaces the store first and installs the new content on that store's first scan, so the window never shrinks to the empty stub in between.

- The new session button switch (`AppSettings.newSessionButton`, key `newSessionButton`, default on, Settings > General) rebuilds the panel content the same way.

- `PanelModel` (owned by `AppDelegate`) holds the `SessionStore` and the `ActionStore` and derives `rows: [SessionRow]` and `actionRows: [ActionRow]` from them on every read, so `@Observable` tracking reaches them. It turns pointer positions into `hoveredKey` or `hoveredActionID`, `isExpanded` and `bulgeRowIndex` (a slot index: session rows first, then the action rows; `rowIndex(atY:)` snaps across the divider band, `slotCenterY` adds `Theme.dividerHeight` beyond it). It also sequences the window geometry: `.expanded` the moment a hover begins, `.collapsed` after `Theme.closeSpringSettleTime` once it ended, cancelled by a re-enter. A pointer on the open bulge keeps the hover; anywhere else off the capsule ends it.
- The new session button sits above the session rows when `PanelModel.showsNewSession`: slot `PanelModel.newSessionSlot` (-1), so row and action indices are the same with or without it. Its slot is `Theme.newSessionPitch` (44 pt) tall, smaller than a row, followed by a `SectionDividerView` whenever anything is below it; the live section moves down by `Theme.topSectionHeight` and the capsule grows by the same amount. With the button there is no empty stub: the button alone shows where the panel lives. It never arrives or departs, `throwTarget` skips it (a press on it still drags the panel) and hidden sessions leave it in place. It is never magnified: `PanelModel.magnify(slot:)` returns identity for its slot, and `MagnifyColumn` treats it as a fixed face (`Face.fixed`, reach `FaceReach.newSession`, the ring), so a magnified neighbour keeps `Theme.rowBodyGap` to it.
- `NewSessionRowView` is the button's row: `ActionBulgeView` (generalised to a title and a detail line) shows "New session" and the route, and `NewSessionGlyphView` hosts `NewSessionHostView`, a ring and a plus as `CAShapeLayer`s filled with their stroke outlines (the snapshot walk fills shape layers, it does not stroke them). The ring is `Theme.newSessionSize` (half a face, 22 pt) across with a 1.5 pt stroke; the 44 pt pitch leaves 19 pt above it, the same as beside it. Hovered, both fade from `Theme.newSessionRestColor` to white and the plus turns 90 degrees (`Theme.newSessionHoverDuration`, ease-out; no turn under Reduce Motion); the ring does not grow. A click bumps `newSessionClickToken`, and the ring dips to `Theme.newSessionClickScale` and back (a fade dip under Reduce Motion). The view reads no pointer, so a pointer move re-evaluates nothing in it. Values live in `Theme`'s "New session button" section.
- `NewSessionLaunch` decides the button's route from the session source: `.desktop` opens `claude://code/new` with no query (a new chat in the Claude app), `.terminal` and `.everywhere` run plain `claude` in the home folder through the terminal launcher (`ActionLaunch.runInTerminal`; an empty prompt means no argument; the file is `new-session.command`). Effects are injected like `ActionLaunch`'s, so tests open nothing.
- `SessionRow` is the value per row: key, pid, source, opener, cwd, name, `FaceStatus`, label, `stateSince`, `hostSessionId`, `ended`, activity, subagent count, branch, project key. The status mapping lives here: ended wins, then needs input, working, and for an idle session just finished (the 8 s done moment), else your turn or idle by its `IdleTier`. Labels: `Needs input`, `Needs permission`, `Needs you`, `Working · <activity>`, `Your turn`, `Idle`, `Finished`, `Ended`. An external row has no activity (`Working`) and its `tool` leads the status line in the bulge: `StateDurationText` draws it as its own text at a lower layout priority, so a long tool name is truncated before the status or the time.
- Acknowledgement: a row click (`PanelModel.tapped`, not the release of a drag or throw) records `Acknowledgements` (a value type, `SessionKey` to date) before opening the chat. An idle period that began at or before the acknowledgement is no longer your turn; a new idle period is eligible again. The clicked row drops to idle and re-sorts below the other your-turn rows through the usual reorder spring. Entries are pruned in `layoutDidChange` with the attention tokens when sessions leave.
- `CapsuleView` draws the goo shape below and the faces and bulge texts on top, laid out at `Theme.contentWidth` and right-aligned, so the window only ever reveals more or less of it. One `SessionRowView` per session (`ForEach(id: \.key)`, so faces keep their identity on reorder), then `SectionDividerView` (a 1 pt line in `Theme.dividerColor`, 60 % of the capsule width, only with both sections present) and one `ActionRowView` per action. The capsule height springs along (`Theme.capsuleHeight(rows:actions:)`). An empty store shows a bare black stub of one row height, or the action faces alone when there are any.
- `BulgeContentView` shows the name and the `Needs input · 2m` status in the row's status colour, left-aligned at the bulge's inner padding and centred in the blob at rest (`PanelModel.bulgeTextPlacement(slot:)`: on the slot, or moved with the flush blob at the first and last slot, see "Goo"), never moved by the goo spring. `RevealModifier` fades each line in staggered (opacity only) and out fast. The whole bulge is the click target.
- `SessionOpener` handles a click: `route(for:)` decides, `perform` acts, so tests check the decision. Claude sessions: `claude://code/continue?session=<hostSessionId>`, else for a terminal or editor session the app hosting its pid (`ProcessAncestry`), else the Claude app by bundle id. External sessions: their `open` (`NSWorkspace` for a URL, the app with a bundle id, or the command through `ActionLaunch.runInTerminal` in front, `open-<id>.command`), else the app hosting their pid, else nothing. `RowPressStyle` is the press feedback (0.96 for 120 ms). `StateDurationText` is the minute clock described above.
- `CapsuleShape` is the notch outline: rounded left corners, concave fillets into the screen edge (tangent to it, so each tip meets the edge in a point at the window's top and bottom), animatable body height. With `side` `.left` it draws the same outline mirrored about its rect's centre.

### Goo

- `Goo/`: `GooState` is the one animatable vector (body height, `.all` widening, bulge width, centre and height); `GooLayout` the shared geometry; `GooView` the renderer switch, which also animates the droplets' lagging centre with `Theme.dropletSpring` and holds the Reduce Motion variant where the bulge only fades. `GooCanvasView` is the `.blurThreshold` renderer: a `Canvas` drawing capsule, bulge blob and trailing droplets into one layer under blur, then alpha threshold, redrawing only while a spring moves. `GooPathShape` is the `.path` renderer: `CapsuleShape` united with the blob and explicit concave fillet pieces. `.sdfShader` falls back to `.path` until a Metal toolchain is part of the build.
- The bulge stays inside the body: `GooLayout.bulgeSpan` is the one rule for its vertical place. Centred on its slot, `Theme.bulgePadding` taller than the slot at each end (the new session button's 44 pt slot gives a 56 pt blob, a row's 64 pt), and at the middle slots never closer than `Theme.bulgeEdgeMargin` (6 pt) to the body's top or bottom. `PanelModel.bulgeSpan(slot:)` applies it to the final layout and `CapsuleView` hands that centre and height to the goo and to the droplets; both renderers keep it inside the live, springing body (`GooLayout.bulgeSpan(state:height:)`), and the row views offset their bulge texts by the same amount (`.row` mode only: in `.all` mode the whole body widens and the texts stay on their slots). The hover region of the open bulge is the same span.
- Flush ends: at the first slot (the new session button, or slot 0 without it) and the last slot (the last action row, or the last session row without actions; `PanelModel.isFirstSlot`, `isLastSlot`) the blob keeps its height and moves until its outer edge is the body's edge (the button's blob 2 pt up, centre 38 pt; a first row's 2 pt up; a last row's 2 pt down). The outline there is one straight line from the blob's rounded left corner to the screen-edge fillet: the capsule's own corner on that side is absorbed (`GooLayout.capsuleCornerRadii`, `CapsuleShape.topCornerRadius` and `bottomCornerRadius`) and no fillet or step remains where blob and capsule meet. A slot that is both first and last (one row alone, the button alone) spans the whole body (68 pt and 60 pt), both edges flush. Before this, the 6 pt margin applied at the ends too, and the goo joined the blob's top to the capsule's top with a concave fillet: a wavy step that did not look natural.
- The flush is animatable: `BulgeSpan.flushTop` and `flushBottom` (1 or 0) travel in `GooState` as `bulgeTopFlush` and `bulgeBottomFlush` and spring with the centre and height. On the way into the first slot the margin, the capsule's corner radius and the fillet between them shrink to nothing together; on the way out they grow back (a test steps the state from the first slot to the second and checks the blob's top and the fillet change in small steps). The drawn weight is also scaled by the blob's reach over `Theme.bulgeFlushReach` (22 pt, `GooLayout.flushWeights`), so a blob that opens or closes at the first slot rises from the margin to flush as it grows, and a nearly closed blob never leaves a square corner behind. With the bulge closed (and in `.all` mode, where the bulge stays closed and the body widens) nothing is flush and the corners stay round. While the body springs (rows arriving or leaving), a flush edge stays on the live body's edge.
- Capsule tips (`.blurThreshold`): the blur (10 pt) is as wide as the edge fillets (10 pt), so blurred, the concave corner between the body and the screen edge filled in: the arc ended about 3 pt short of the edge at the window's top and bottom, the window edge cut that black flat, and the body's top edge bent up from about 20 pt before the edge. So the fillets no longer go through the blur. `GooLayout.capsuleCore` is the blurred part: the capsule without fillets, its body continued past the screen edge by `Theme.gooBleed` between the body's top and bottom only (no full-height bezel any more). `GooLayout.capsuleTips` is a crisp pass drawn after the filtered layer: the two fillet regions cut from the exact `CapsuleShape` outline, reaching `Theme.gooTipOverlap` (4 pt) into the body where the core has the same straight edge, mirrored past the screen edge so the pass's own edge soften neither lightens the edge column nor thickens the tip. Inside the window, core and tips together are exactly the outline (a test samples it). The window frame did not change.
- Flush junction (`.blurThreshold`): with the flush edge on the body's edge, the core's corner on that side and the blob's inner corner (inside the capsule) are square (`GooLayout.bulgeBlob`), so the blurred layer holds one straight edge from the blob's rounded corner to past the screen edge, and a straight edge with solid below thresholds at 0.5 exactly on itself; nothing is extended or clipped. Rounded, the two corners left a notch about 2 pt deep that the blur turned into a dip. A test rasterises core and blob, blurs them with a Gaussian of `Theme.gooBlur`, cuts at `Theme.gooThreshold`, adds the crisp tips and checks the edge column by column from left of the junction to the screen-edge fillet, top and bottom (the same simulation shows the old 6 pt step). It runs off the main actor: the suite is `@MainActor`, and two seconds of main-actor work made other suites' timing tests time out. Measured in snapshots (2x): the edge varies by at most 0.2 px across the junction, against a 12 px step before.
- `.path` renderer: the blob's left corners are rounded, its right side is square and reaches `Theme.bulgeOverlap` into the capsule (the old blob rounded all four corners, which left a notch next to the capsule). Its fillets (`GooPathShape.fillet`) rest on the blob's edge and touch the capsule's straight side or, near the body's ends, the rounded corner's arc, so the join is concave there too. A square corner is an arc of radius 0: the fillet disc then passes through the corner point and shrinks to nothing as the edge rises to the body's top; a flush edge is collinear with the body's and its fillet is empty. A test bisects the outline along the flush edge and finds the same y everywhere from the blob's corner to the screen-edge fillet.
- Filter order (verified visually): `GraphicsContext` applies filters in reverse order of adding, so `GooCanvasView` adds the threshold before the blur. All fills go through one `drawLayer`, otherwise nothing merges.

### Row arrival and departure

Every number is in `Theme`'s Rows section (`UI/RowEntrance.swift`).

- Room first, then the face. A new row's slot opens from 0 to `Theme.rowPitch` (ease-out, `rowOpenDuration` 0.22 s; the stack has no spacing, so the slot's height alone slides the neighbours apart, `RowSlot`) and the goo body grows on the same curve (`PanelModel.gooAnimation(capsuleHeight:reduceMotion:)`; `GooCanvasView` centres its drawing in its actual, still animating frame, otherwise the body lagged the rows by about 10 pt).
- `rowOpenDuration - rowEnterOverlap` after the insertion the face pops in its own layer tree (`EyeAnimations.enter` on the `face` layer, between the magnification and the rest scale): fade in, a `CASpringAnimation` from `rowEnterScale` 0.55 on `rowEnterSpring` (response 0.42, bounce 0.25, converted by `EntranceSpring`), the hop's squash at the spring's first landing, lids closed until the spring settled, then open. The loops start after that.
- Rows arriving in one change stagger top to bottom by `rowEnterStagger` (at most `rowEnterStaggerCap` steps). The first layout opens no slots; its faces only stagger.
- Departure is quieter: one linear progress over `rowLeaveDuration` + `rowCloseDuration` (`RowDeparture`) shrinks the face to `rowExitScale` 0.8 and fades it, then closes the slot. The body follows on `SlotCloseCurve`, a `CustomAnimation` that holds for the face phase and then takes the slot's curve.
- Measured on the way: the stack's own transaction animation drives a removal transition (with the close spring there the slot closed in on a face still showing, so `PanelModel.layoutAnimation` returns the linear departure progress on a shrink); SwiftUI dropped `.delay` on both the combined transition and the goo's `.animation(_:value:)`; and per-frame SwiftUI scale and opacity never reach the AppKit-hosted face, so the face's share travels as `FaceLeave` through the environment to the host layer.
- Open issue: on screen the body still trails the closing rows by about one capture (around 80 ms), although the drawn values match per frame.
- An ended face lingers `DataTuning.endedLinger` with closed eyes first. Under Reduce Motion everything fades and slots open and close at once.

### Faces

- `Eyes/` (dot-matrix style): `EyeParameters` + `EyePathBuilder` (shape model, constant path structure), `Expression` + `ExpressionPoses` (tuned literals), `EyePreset` + `FaceIdentity` (seeded identity, FNV-1a), `FaceStatus` + `FaceProgramBuilder` (status to expression, colour, glow and loops), `ExclamationPose`, `BreathLoop`, `PathTrack` + `EyeAnimations` + `EyeLayerTree` (Core Animation, no timers: blinks, darts, reading scan, gaze wander, breath, pulse, mood flicker all run in the render server), and `FaceView`, the API the panel uses.
- `Eyes/Blob/` (blob style, the default): one coloured body with two capsule eyes cut into it, in the spirit of the MIT-licensed bloub engine (mechanics only; silhouettes, palette and expression values are our own). `BlobProfile` (a silhouette as 64 polar radii, Catmull-Rom cubic path with a constant element count so Core Animation morphs it), `BlobShape` (formula silhouettes: round, squircle, pebble, bean, drop, pill, soft hex, cloud, and the action star), `BlobBody` (shape plus squash; in `.status` shape mode: drop = needs input, cloud = working, pill = idle and just finished, pill swapping with round = your turn, flattened pill = ended), `BlobEyes` (eyes on an imaginary sphere, projected orthographically, so the eye nearer the rim narrows), `BlobExpressions` (tuned poses), `BlobBlinkSchedule` + `BlobMotion` + `BlobTrack` (pose-of-time loops sampled into path keyframes), `BlobProgramBuilder` (status table: shape, colour, loops), `BlobShapeSwap` (the your-turn swap and hop), `BlobLayerTree`. `Theme.blobShapeMode` decides whether the silhouette carries the status (default) or the seed.
- Colour: `Theme.colorMode` decides what the body colour means. `.status`: amber needs input, cyan working, mint flash just finished, `Theme.yourTurnColor` (a muted mint between the flash and idle) your turn, `Theme.idleColor` (a muted warm grey, the old soft white's hue at a lower value) idle, grey ended. `.project`: a hue per project from `ProjectColor`, hashed from the project key (the last path component of `cwd`), so every session of one repo shares it; needs input stays amber, just finished flashes mint, your turn keeps the project colour undimmed, idle is the project colour dimmed by `Theme.projectIdleDim`, ended grey. `.identity`: a seeded palette colour per session. In every mode your turn adds a halo and an edge cue in the row's own body colour (`Theme.yourTurnColor`, the project colour or the identity colour); needs input stays amber everywhere. `FaceLook.bodyColor(for:seed:projectKey:)` is the one resolution: it calls the style's program builder colour (`BlobProgramBuilder.color`, `FaceProgramBuilder.color`), so `CapsuleView` hands the cue the same colour the face shows. The dot-matrix style shows your turn as the idle program in the your-turn colour at the full glow (`Theme.glowOpacity`; idle glows at `Theme.idleGlowOpacity`). `Theme.projectPalette` keeps out of the amber wedge (amber only ever means needs input) and the violet wedge (that belongs to the action faces).
- `Eyes/Filters/`: the screen filters applied to both styles (`DotGridMask`, `AsciiGridMask`, `HalftoneMask`, `ScanlineMask`). All are pre-rendered images cached per size and scale; nothing runs per frame.

### Visual states

- Working substates come from the last tool call in the transcript tail (`SessionActivity`): thinking (default), coding (eyes narrow, gaze steps across a typed line), running (eyes flick down-left and pulse like a cursor), reading (two lines read left to right), delegating (eyes look up, slow blinks). Each runs a little faster or slower per seed, so working faces never move in step.
- Subagent satellites: up to `Theme.satelliteMax` small blobs orbit a working face, one per live subagent.
- Urgency, top to bottom: needs input (amber, needs an action), your turn (muted mint, waiting for the next instruction), idle (muted grey, parked). Waiting, just finished and your-turn rows draw above idle neighbours.
- Attention: `FaceStatus.needsInput(kind:)` carries the `WaitingKind`; the label reads `Needs input` (question), `Needs permission` (permission prompt) or `Needs you` (anything else). A waiting face hops on entry, sits at `Theme.attentionScale`, grows to `Theme.attentionGrowScale` and back every `Theme.attentionGrowInterval` (`BlobAnimations.grow`, seeded phase), and has an amber halo behind it. The halo (`BlobHalo`) is shaped like the body: the body's profile at its rest scale (1.08 for a waiting face), every radius scaled by `Theme.haloScale` (1.22) and held at `BlobHalo.fillCap`, drawn as the shadow of that path (`shadowPath` on a `CAShapeLayer` with no fill, `shadowRadius` `Theme.haloSoftness`, 2 pt). Core Animation's `shadowRadius` is the Gaussian sigma (measured with `CARenderer`), so the rim counts as spent `Theme.haloTailSigmas` (2) sigmas beyond the fill, about 2 % alpha; the cap keeps that point, at the top of the hop swell, inside `Theme.haloOuterRadius` (26 pt), so two lit rows keep a dark gap and no glow reaches the desktop, and `haloClip` still clips it to the row cell. Geometry decides where the glow shows: the pill is 42 pt wide in a 52 pt bound, so its long sides and the round are capped and show only a soft rim, while above and below the pill the scaled outline gives a 3 pt band plus the soft rim; the waiting drop at 1.08 is capped all round and glows below and beside it. The glow does not follow the genie stretch or the magnification, only the drift and the lift of every hop: the attention hop's lift runs on the halo's host too (`oneshot.hopLift`, `BlobAnimations.hopLift`, additive, the same clock as the face's `oneshot.hop`, no squash), so the glow rises with the body inside `haloClip`. The capped drop's glow then comes within a fraction of a point of the row's edge and the clip trims about half its rim there; the hop plays as the face starts waiting, while its glow still fades in, so that edge stays faint. Its host layer carries the peak opacity and the loop runs relative to it, so a halo change eases on the host; the glow layer's own model opacity is the rest level, which is what Reduce Motion shows, steady. The host and the glow are face squares centred in their superlayers, and a test converts the centre of every halo and burst layer and of the glow's path to the root and checks it against the face centre, and that every silhouette's glow is spent inside the outer radius. A Gaussian blur filter (`CIGaussianBlur` in `filters`) on a filled path looks the same but cost WindowServer about 5 % of a core with four lit faces where the shadow cost nothing measurable, so the shadow it is plus a 2 pt amber line on the capsule's left edge beside the row (`AttentionEdgeCue`, `AttentionEdgeLayout`, `AttentionEdgeCueView`; it hides while that row's bulge is open). A permission prompt pulses faster (`Theme.permissionPulsePeriod`) and grows more often (`Theme.permissionGrowInterval`). Nothing grows under Reduce Motion.
- Excited: the moment the person's message arrives. Typing cannot be seen from outside the session, so the trigger is the registry status: a row whose face showed idle, sleepy, your turn, just finished or needs input (registry idle or waiting) and now shows working. `ExcitedTracker` (`UI/ExcitedTracker.swift`, the same shape as `AttentionTracker`) holds the rule: never on a session's first appearance (launch, a row that arrives working), never working to working (a new activity). `PanelModel.noteStatus` bumps the row's `excitedToken`, the row hands it to the face (`FaceView.excited(token:)`), and a face whose program has the flag (`BlobProgram.excited`, set for the working status only; not an action launching) plays `BlobLayerTree.excite`: as the blink of the state change opens (`transitionEnd`; at once without one) the eyes widen to `Theme.excitedEyeScale` and look at the person (`BlobProgramBuilder.excitedTrack`, `oneshot.excited`), the face hops twice (`BlobAnimations.excitedHops` on `face`, the glow's host lifting with it), the body wiggles and squashes on landing (`excitedWiggle` on the scaler), and the body brightens toward white by `Theme.excitedBrighten` and eases back (`excitedColor`, replacing the state change's `color.fill`). The working loops are re-installed to start where it ends, after `Theme.excitedDuration` (0.62 s). One-shots only, so nothing is left running; a halo from the old state fades as usual. Nothing under Reduce Motion beyond the state change. The dot-matrix style ignores the token. Measured with four fixture sessions after the burst: 0.0 % CPU, 28 MB.
- Done moment: a busy to idle transition flashes mint with a bounce, sends a burst of `Theme.doneBurstCount` dots out from behind the body (`BlobBurst`, `BlobAnimations.burstDot`, layers removed in a `CATransaction` completion) and holds the mint with a breathing halo (`Theme.doneHaloOpacity` 0.6, `Theme.doneHaloPulse`: from `Theme.haloBreathLow` 0.4 of the peak to the peak and back in 1.8 s, eased in and out) for `Theme.doneHold` (equal to `DataTuning.justFinishedDuration`, 8 s). Then it eases into your turn without a blink (`BlobLayerTree.glides`: the same pill, so the eyes glide to the your-turn gaze over `Theme.yourTurnGlideDuration` while the colour and the halo cross-fade; the halo breath keeps running when both halos share it). The your-turn swap starts only after the glide (plus its seeded offset); the done bounce is long over by then.
- Your turn: `FaceStatus.yourTurn(since:)`. Catches the eye, clearly below amber: the body in its colour mode's colour (`Theme.yourTurnColor` in `.status` mode); normal eyes looking at the person (the needs-input yaw) with the idle blink rhythm and no wander (`yourTurnTrack`), no attention scale, no grow. In `.status` shape mode the body swaps between `Theme.yourTurnShapes` (pill and round): each holds `Theme.yourTurnSwapHold` (1.4 s), then morphs to the other in `Theme.yourTurnSwapDuration` (0.35 s, ease-in-out), one `loop.swap` path keyframe animation on the body and its mask (`BlobShapeSwap`, `BlobAnimations.shapeSwap`; constant element count, so it morphs). With every swap the face hops `Theme.yourTurnBounceHeight` of its size (3 pt) on the scaler, ease-out up and ease-in down over `Theme.yourTurnBounceDuration`, then a tiny landing squash (`loop.bounce`, additive, `BlobAnimations.swapBounce`). Both start a seeded fraction of a cycle late (`FaceIdentity.swapPhase`) on the resting pill, so nothing jumps and faces never swap in step. In `.identity` shape mode (or with a forced body) only the hop plays. Under Reduce Motion neither: the face holds the pill. A hovered face (any hover effect) rests: swap and hop ease back to the pill and the ground (`settleSwap`, `Theme.yourTurnSettleDuration`) and start again `Theme.yourTurnSwapHold` after the hover. A state change hands the silhouette on screen to the usual morph. `FaceReach` counts the larger silhouette plus the hop (the pill alone while hovered). A halo in the body colour at `Theme.yourTurnHaloOpacity` (0.5, below the done and the amber halo) breathing on `Theme.yourTurnHaloPulse` (the done breath, so the glide keeps it running; a low end of 0.3 left the glow invisible at the bottom of the breath on coral and purple project colours, 0.4 still reads). The glow runs the swap with the body: `loop.swap` on its `shadowPath` with the scaled pill and round, the same keyframes and begin time, and `settleSwap` and the status-change `morph` (same delay and duration as the body's) take it along; `BlobProfile`'s constant element count keeps the morph clean. With each hop the glow swells to `Theme.haloHopSwell` (1.06) about the face centre, up while the face is in the air, fullest on the landing squash, back over `Theme.haloHopSwellRelease` (`loop.haloSwell`, additive, `BlobAnimations.haloSwell`, in step with `loop.bounce`). The glow also lifts with the hop: `loop.haloLift` on the halo's host (`BlobAnimations.swapLift`) runs the body's lift keyframes, curves, beat, period and begin time without the squash (that stays on the body), and `settleSwap` lands it with the body (`swap.settleBounce` on the host, from the lift on screen). The lift happens inside `haloClip`, which stays on the row: at the top of the hop the round's glow reaches about 2 pt past the row's edge, where its rim is under 8 % alpha, and the clip trims that (a test computes it). The edge cue in the body colour at `Theme.yourTurnEdgeOpacity` (below amber's), breathing with the halo. Under Reduce Motion the halo and the cue rest steady at their rest level, and nothing swells. When the window closes, or the person clicks the row, it becomes idle through the usual status-change blink. `Theme.sleepyAfter` (30 minutes) is at least `Theme.yourTurnFor`, so a face never goes sleepy while it is your turn.

### Hover

- `Theme.hoverEffect` (default `.magnify`) is Dock-style magnification. `PanelModel` keeps the pointer in capsule coordinates and derives one `MagnifyState` (scale, dx, dy) per slot: `scale = 1 + (Theme.magnifyMax - 1) * exp(-(d / Theme.magnifySpread)^2)` with `d` the pointer's vertical distance to the slot centre (1.28 under the pointer, about 1.12 one pitch away, 1 beyond two), clamped so the face stays `Theme.magnifyMargin` inside the capsule width. The follow leans every face toward the pointer by up to `Theme.followX` / `Theme.followY`, weighted by the same falloff. The row pitch never changes.
- `MagnifyColumn` fits each state so no body comes closer than `Theme.rowBodyGap` to a neighbour, the divider line or the capsule's end: `FaceReach` gives each face's reach above and below its centre at the peak of its loops, two neighbours share the pitch less the gap, the spare room going to the face nearer the pointer. A fixed face (the new session button) stays at identity and keeps exactly its own reach of a shared room; the neighbour gets the rest.
- Hovering a waiting face takes its attention scale over: the scaler eases to 1 and the grow loop pauses, while the pulse and halo keep going; both come back on release. Hovering a your-turn face pauses its shape swap and hop the same way (under every hover effect), so nothing hops under the pointer. A waiting or just finished row draws above idle neighbours, the hovered row above all.
- `MagnifiedFaceView` is the one view that reads the pointer, so a move re-evaluates only the faces. `FaceView.magnify(_:)` hands the state to the layer tree, which sets a dedicated `magnify` layer's model transform and eases there with `BlobAnimations.magnify` (`Theme.magnifyFollowDuration` per pointer event, `Theme.magnifyReleaseDuration` back to identity on exit). Nothing runs while the pointer is outside.
- `.stretch` is the genie: the hovered face stretches toward the bulge (`BlobGenie.stretched` scales the 64 radii toward the left, constant element count so the path springs), on a `CASpringAnimation` with visible overshoot, the one elastic motion in the app. `.none` leaves the faces alone; the bulge still opens.

### Throw a face out

Throwing a session face out of the capsule stops watching that session.

- The rules below are written for the right edge; on the left edge (`PanelSide.left`) left and right swap: the throw goes to the right and the face flies off rightward.
- A press on a session face that first travels more than `Theme.throwThreshold` (10 pt) to the left, before `Theme.dragThreshold` vertically, holds the face instead of dragging the panel (`PressAxis.decide`, once per press in `PanelDragController`). Vertical first is the panel drag exactly as before; when both thresholds pass in one event, the larger travel wins. Action faces cannot be thrown.
- While held (`FaceThrow`), the face follows the pointer 1:1 horizontally and by `Theme.throwVerticalFollow` vertically, tilted up to `Theme.throwTilt` degrees with its horizontal velocity, drawn on top (`Theme.throwZIndex`). The bulge closes, the hover and pointer reports freeze, the window stays expanded and the slot stays open. The pose (`FaceThrowPose`) reaches the face as a value and is set on the face host's root sublayer transform, composed with a departing row's `FaceLeave` (Core Animation, no SwiftUI layout per move).
- Released with the face centre more than `Theme.throwDistance` (70 pt) left of the capsule, or moving left faster than `Theme.throwVelocity` (600 pt/s, measured over the last `Theme.throwVelocityWindow` of moved samples, so a rest before the release reads zero), the face flies on in its direction (at most 45 degrees off the horizontal) by `Theme.throwFlyDistance` over `Theme.throwFlyDuration`, shrinking to `Theme.throwFlyScale` and fading. Then the session is hidden and the row departs like any other. Otherwise the face springs back on `Theme.throwReturnSpring`.
- Reduce Motion: no tilt, the fly-away is a plain fade, the return a plain ease.
- Hidden sessions live in `HiddenSessions` (`UI/HiddenSessions.swift`, `UserDefaults` key `hiddenSessionPids`: an array of `{pid, startedAt}` dictionaries (`{external, startedAt}` for a session from another tool, `external` being its id), `startedAt` in the registry's epoch milliseconds, so a reused pid is not hidden). `PanelModel.rows` and the capsule size skip them, a hidden session that starts waiting stays hidden, and entries whose session left the registry are pruned on the next change of the session list. Pruning checks every live key of the scans (`SessionStore.presentKeys`), not only the shown source's, so a session hidden under one "Show sessions from" setting stays hidden after switching away and back; with sessions from other tools off, external entries are kept as they are (`keepsExternal`).
- The menu's "Show hidden sessions (<n>)" clears the list; the rows arrive with the arrival animation. It is disabled while nothing is hidden.

### Action faces

- `Data/Actions/` and `UI/ActionRow*.swift`. `ActionItem` (`id`, `name`, `cwd`, `prompt`, optional `seed`, `symbol`, `shape`, `color`, `days`) decodes `actions.json`. `ActionStore` reads `~/Library/Application Support/Wallflower/actions.json` (created as an empty list on first launch, so the app ships with no actions) and reloads on change (`ActionFileWatcher`, a vnode source on the file and its folder, debounced; a broken file keeps the last list). "Edit JSON…" in Settings opens it.
- Weekdays: an item's optional `days` (`["thu", "fri"]`; keys `mon` to `sun` in any case, locale independent) limits it to those days. Nil, empty or no known key means every day, unknown keys are ignored, and `days` is omitted from the file when nil. `ActionSchedule` is the pure logic (`isShown(days:on:calendar:)`, `nextDayChange(after:calendar:)`, the toggle rules). `ActionStore.actions` keeps every item (Settings edits them); `visibleActions` is the list for `today`, in file order, and `PanelModel.actionRows` reads it, so a face that starts or stops showing at midnight takes the normal arrival or departure path. `today` moves on through one one-shot timer at the next local midnight (re-armed when it fires, `DataTuning.dayChangeTolerance`) plus `NSCalendarDayChanged`, `NSSystemClockDidChange` and `NSSystemTimeZoneDidChange`, which cover a wake past midnight (a timer does not count the time asleep). Nothing polls.
- Settings > General > Actions is the editor (`Settings/ActionsSettingsSection.swift`, logic in `Settings/ActionEditorModel.swift`, an `@Observable` model the Settings window owns, so it is tested without a window). The list shows every item in file order (name, days caption, folder and the first line of the prompt) with a bar below it: add, remove, move up, move down, Edit…. Click selects, double-click or Return edits, Delete removes, the arrow keys step the selection, and a row dropped onto another takes its place (`ActionEditorModel.moveItem`). Up to four rows show (`ActionListView.listHeight`, half a row more when it scrolls), so the window stays short; the list scrolls inside. It is a `ScrollView` with `scrollPosition(id:)`, not a `List`: nested in the grouped `Form`, neither a `List` nor a `ScrollView` moved for `ScrollViewProxy.scrollTo` (the clip view's origin stayed at 0), and only the keys, the move buttons and a new action reveal a row (`reveal()`), since a click selects a row already in sight. The tab keeps `.scrollDisabled(true)`; the list overrides it while it has more rows than fit.
- The sheet (`ActionEditorSheet`) edits one action: Name, Folder (a text field plus "Choose…", an `NSOpenPanel` for a folder whose choice is written with `~`, `ActionEditorModel.displayPath`), Prompt (multi-line) and the seven day toggles (`Settings/WeekdayToggles.swift`, Monday first). Every change writes the whole list through `ActionStore.save` (atomic, then sets `actions` at once; the watcher's reload finds the same list), so the panel follows live and `actions.json` stays the source of truth. An existing action saves on every keystroke, trimmed, and closes with Done; a blank name or folder is not saved (the file keeps the last good value) and keeps Done disabled. A new action is a draft until Add, which makes its id. Keys the editor does not show (`seed`, `symbol`, `shape`, `color`) are kept. A change made in the file while the sheet is open reaches the sheet (`sync()`, which compares with what the sheet last loaded or saved, so its own saves never undo typing); an action that left the file closes its sheet.
- Ids (`Data/Actions/ActionID.swift`): made once, from the name an action is added with, and never changed by a rename, because the id names the face's seed and the `launch-<id>.command` file. `ActionItem.slug(for:)` transliterates to Latin, folds diacritics and case (`ß` becomes `ss`), turns every run of characters other than `a-z` and `0-9` into one `-`, trims dashes and cuts at 32 characters; nothing left gives `action`. `ActionItem.makeID(for:existing:)` adds `-2`, `-3` and so on when the slug is taken, compared without regard to case (the launch files of `Review` and `review` would be one file on a case-insensitive disk).
- Days: all seven on is stored as no `days`; the last day that is on cannot be turned off, so no item is hidden on every day.
- The face is `FaceMode.action(ActionFace)`: `Theme.actionShape` (the four-point `BlobShape.star`, which no session wears) in `Theme.actionColor` (lavender), calm resting lids that open on hover, a one-shot glee squint on click, then the working cloud while the launch feedback runs.
- `ActionLaunch` starts the session; `Theme.actionLauncher` picks how:
  - `.terminalCommand` (the default) writes a `launch-<id>.command` file into the Application Support folder and opens it in the default terminal app without bringing it forward (`Theme.terminalOpensInBackground`), where `claude "<prompt>"` runs at once in the action's folder. Symlinks in the folder path are resolved, so the CLI sees the path it already trusts. No Accessibility needed, but the session runs outside the desktop app. It became the default because the desktop route needs the workspace trusted in the Claude app and, without Accessibility, a Return by hand.
  - `.deepLinkAndSend` (the Claude app route) opens `claude://code/new?folder=<cwd>&q=<prompt>`, waits for the Claude app (`com.anthropic.claudefordesktop`) to become active (at most `Theme.actionActivationTimeout`), then `ActionSender` reads Claude's focused element through Accessibility every `Theme.actionPollInterval` and acts on what the composer holds (`ActionLaunch.composerState`, `ActionLaunch.sendStep`): a defused prompt is retyped, the prompt gets a Return, a slash command that the first Return picked from the menu gets another, and an empty composer after our Return counts as sent once it stayed empty for `Theme.actionSentConfirm`. Any other text is never touched, so a draft elsewhere in Claude is never sent.
  - `.deepLinkNew` only prefills.
- Settings > General > "Run actions in" (Terminal or Claude app) chooses between `.terminalCommand` and `.deepLinkAndSend`; the Accessibility row only matters for the Claude app.
- Why key presses at all (Claude app route): the Claude app's handler reads only `q` (alias `prompt`), `folder`, `file` and the `ssh_host` / `ssh_port` / `ssh_folder` trio from `claude://code/new` and drops every other parameter, so no URL can make the page submit. The page also defuses prefilled text: a leading `/` arrives as U+FF0F, a leading `!` as U+FF01, `@` mentions as U+FF20. A prefilled `/review` sent as is would be plain text and no command would run, hence the retype.
- Why a loop and not one wait (measured with the Claude app in October 2026): the prefill lands 0.1 to 2.4 s after the link; when a new-session page is already showing, it keeps its older prefill for up to about half a second before the route reloads, and a Return on it is lost; opening the very same link again while Claude is frontmost reloads nothing.
- Guards: at most `Theme.actionMaxKeyActions` key actions; every key press goes to Claude's process only (`CGEvent.postToPid`) and only while `ActionLaunch.shouldSend` holds (Claude frontmost and less than `Theme.actionSendWindow`, 8 s, since the link opened). Without Accessibility, or when a guard refuses, the prompt stays prefilled and the bulge's second line reads "Press Return in Claude" in amber for `Theme.actionSendHintDuration`. The first click asks with the system prompt (`AXIsProcessTrustedWithOptions`).
- Claude app route: an action's `cwd` has to be a workspace the Claude app already trusts. For any other folder the app shows "Trust this workspace?" and the new-session page sits behind it with an empty composer, so the loop presses nothing at all and the bulge shows the hint.

### Welcome

- `Onboarding/`: `WelcomeModel` (page, choices, outcome), `WelcomeView` (four pages, `WelcomeStyle` metrics), `WelcomeWindowController`.
- The "Set up" card is `WelcomeStyle.setUpCardWidth` (380 pt) wide and both rows keep `WelcomeStyle.setUpInset` (16 pt); the hairline spans the card. "Where do you run Claude Code?" is `WelcomeSourcePicker`, an `NSSegmentedControl` with `fillEqually` segments sized to the content width and the short labels (`SessionSource.shortTitle`: Claude app, Terminal, Everywhere; Settings keeps `title`). SwiftUI's segmented picker never grows past its labels' natural width, and with the long labels that width (402 pt, measured in a hosting view) was wider than the card's 348 pt of content, so the control and the switch row could stick out past the card's right edge. The selection is a neutral grey (`selectedSegmentBezelColor`), not AppKit's blue accent in a key window: the welcome's one accent is mint. `WelcomeLayoutTests` lays the page out in a hosting view and checks the frames.

### Playground

`Playground/` is the face playground (`--playground` opens it at launch).
